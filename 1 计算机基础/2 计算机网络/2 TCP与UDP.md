# 2 TCP 与 UDP

## 2.1 TCP 特性

TCP 是面向连接、可靠、有序的字节流协议。它通过序列号、确认、重传、校验和、滑动窗口和拥塞控制尽量保证数据交付。

三次握手用于交换初始序列号并确认双方收发能力；四次挥手用于独立关闭两个方向的数据流。连接建立和关闭都可能受丢包、半连接、TIME_WAIT 和中间设备超时影响。

TCP 不保留应用消息边界。一次 `write` 可能被拆成多次 `read`，多次写入也可能被合并，因此应用协议必须自行定义长度、分隔符或帧格式，并循环读取直到一条完整消息到达。

## 2.2 流量控制与拥塞控制

接收窗口限制发送方不要超过接收端处理能力；拥塞窗口根据网络拥塞状况限制发送速率。实际可发送数据通常受两者较小值约束。发送缓冲区、接收缓冲区和应用读取速度都会影响吞吐与延迟。

拥塞控制会经历慢启动、拥塞避免和丢包后的调整。大量短连接、丢包、接收端读取慢或服务端处理慢，都可能表现为吞吐下降，不应只靠调大 socket 缓冲区解决。

## 2.3 UDP 与 QUIC

UDP 无连接、不保证顺序和可靠交付，适合实时音视频、DNS、服务发现和由应用自行设计可靠性的协议。使用 UDP 时必须明确丢包、重复、乱序、放大攻击和 MTU 处理策略。

QUIC 基于 UDP 实现可靠字节流、多路复用和 TLS 1.3 握手，单条流阻塞不会阻塞其他流，并支持连接迁移。它的可靠性来自 QUIC 层而不是 UDP 本身。

## 2.4 常见连接问题

- `connect timeout`：可能是路由、防火墙、地址错误或服务未监听。
- 建连成功但请求超时：可能是服务处理慢、连接池耗尽、读取阻塞或应用协议不完整。
- 大包失败、小包成功：优先检查 MTU、路径 MTU 发现和分片策略。
- 连接大量处于 `TIME_WAIT`：检查短连接模式、连接复用、客户端端口范围和服务端关闭方式。

客户端应设置连接、读写和整体请求超时；连接池要限制总连接数、空闲连接和单主机连接数，并在服务端重启、网络切换时处理失效连接。
