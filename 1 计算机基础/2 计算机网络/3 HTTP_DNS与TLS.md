# 3 HTTP、DNS 与 TLS

## 3.1 HTTP

HTTP 是请求-响应协议。请求由方法、目标、首部和可选消息体组成，响应包含状态码、首部和消息体。

| 方法 | 常见语义 | 幂等性 |
| :--- | :--- | :--- |
| GET | 获取资源 | 是 |
| POST | 创建或触发处理 | 通常否 |
| PUT | 完整替换资源 | 是 |
| PATCH | 部分更新资源 | 取决于设计 |
| DELETE | 删除资源 | 通常是 |

幂等表示重复执行最终效果相同，不代表每次响应完全一致。超时重试前要确认操作是否幂等；非幂等请求可使用业务幂等键、请求去重和状态查询降低重复执行风险。

HTTP/1.1 依靠连接复用减少握手；HTTP/2 在一条连接上多路复用并压缩首部；HTTP/3 使用 QUIC。升级协议不能替代合理的超时、限流、认证、输入校验和错误处理。

## 3.2 DNS

DNS 将域名解析为地址，也可以提供服务发现、别名和邮件路由等记录。解析过程可能经过浏览器缓存、操作系统缓存、递归解析器和权威服务器。

常见记录包括 A、AAAA、CNAME、NS、MX 和 TXT。TTL 决定缓存时间，但不保证所有客户端在 TTL 到期前后立即看到同一结果。变更域名解析时应提前降低 TTL，并准备旧地址继续服务的过渡时间。

DNS 轮询可以分散流量，但不等价于健康检查和负载均衡。客户端应处理多地址、地址顺序变化、IPv4/IPv6 失败和解析暂时不可用。

## 3.3 TLS

TLS 通过证书认证服务端身份，并协商密钥保护机密性和完整性。客户端应校验证书链、域名、有效期和信任根，不能因为“测试方便”而关闭校验。

TLS 握手会带来额外延迟；连接复用、会话恢复和合理的证书链可以降低成本。证书应设置到期监控和自动续期，私钥要限制访问权限并准备轮换流程。

## 3.4 代理与安全

反向代理可以承担 TLS 终止、路由、限流、压缩和观测，但必须正确传递协议、客户端地址、请求 ID 和超时。应用不能无条件信任来自任意请求的 `X-Forwarded-For` 等首部。

HTTP 服务至少应考虑认证、授权、输入校验、请求体大小、CORS、CSRF、敏感信息脱敏和重放风险。错误响应向客户端返回必要信息即可，详细堆栈应留在受控日志中。
