# 1 网络分层与基础概念

计算机网络通过协议让不同主机交换数据。分层的价值是隔离变化：应用关注业务消息，传输层关注端到端交付，网络层负责跨网络寻址，链路层负责相邻节点传输。

## 1.1 TCP/IP 分层

| 层次 | 主要职责 | 常见协议或设备 |
| :--- | :--- | :--- |
| 应用层 | 定义业务消息和交互语义 | HTTP、DNS、SMTP、WebSocket |
| 传输层 | 端到端连接、可靠性、复用和流量控制 | TCP、UDP、QUIC |
| 网络层 | IP 寻址和跨网络转发 | IPv4、IPv6、路由器 |
| 链路层 | 相邻节点传输、帧和介质访问 | Ethernet、Wi-Fi、交换机 |

发送数据时，上层消息会逐层封装头部；接收端反向解封装。每层的 MTU、超时、重试和错误语义不同，排障时要确认问题属于哪一层，避免把应用超时直接归因于网络不通。

## 1.2 地址与端口

- MAC 地址用于链路层相邻节点通信，通常由交换机学习并转发。
- IP 地址用于网络层标识主机或接口，路由器根据路由表转发数据包。
- 端口用于在同一主机上区分不同传输层服务。
- Socket 通常由协议、源地址/端口和目标地址/端口共同确定。

IPv4 地址不足催生了 NAT；NAT 允许多个内网主机共享公网地址，但会影响端到端连接和入站访问。IPv6 提供更大的地址空间，但应用仍需正确处理地址格式、双栈连接和 DNS 返回多个地址的情况。

## 1.3 延迟、带宽与吞吐

带宽是链路单位时间的传输能力，延迟是数据从一端到另一端所需时间，吞吐是实际完成的数据量。高带宽不代表低延迟；跨地域访问常受传播延迟和排队影响。

请求耗时通常包含 DNS、连接建立、TLS 握手、服务处理、排队和响应传输。连接复用、缓存、压缩和合理的数据包大小可以降低成本，但应通过真实指标验证。

## 1.4 网络排障路径

1. 确认域名解析结果、目标地址和端口。
2. 确认本机路由、代理、防火墙和安全组。
3. 检查 TCP 建连、TLS 握手和应用层响应是否分别成功。
4. 对比客户端、服务端和中间代理的日志与时间戳。
5. 观察丢包、重传、RTT、连接数、队列和带宽使用率。

`ping` 失败不一定表示 TCP 服务不可达，`telnet` 或端口探测成功也不代表 HTTP 业务正常；测试工具必须与待验证的协议层匹配。
