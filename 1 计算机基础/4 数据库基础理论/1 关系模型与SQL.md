# 1 关系模型与 SQL

关系数据库用表、行和列表示数据，通过主键标识记录，通过外键表达表间关系，并使用约束维护数据不变式。SQL 同时包含数据定义、数据操作、查询、事务和权限等能力。

## 1.1 约束与范式

常见约束包括 `PRIMARY KEY`、`UNIQUE`、`NOT NULL`、`CHECK` 和 `FOREIGN KEY`。约束应优先表达数据库必须保证的事实，例如金额不能为负、订单必须属于存在的用户。

规范化通过拆分重复数据减少更新异常：插入异常、删除异常和修改异常。第三范式通常要求非主属性不依赖其他非主属性。适度反规范化可以减少连接和提高读取效率，但必须明确同步来源和一致性代价。

## 1.2 SQL 查询逻辑

SQL 的常见逻辑处理顺序是 `FROM/JOIN`、`WHERE`、`GROUP BY`、`HAVING`、`SELECT`、`DISTINCT`、`ORDER BY`、`LIMIT`，与书写顺序不同。`WHERE` 过滤行，`HAVING` 过滤分组；聚合查询中未聚合列必须符合数据库的分组规则。

连接查询要明确内连接、左连接和连接条件。把右表条件错误地写入 `WHERE`，可能把左连接变成内连接。`NULL` 表示未知或缺失，不能用 `= NULL` 判断，应使用 `IS NULL`；三值逻辑会影响过滤和 `NOT IN` 的结果。

## 1.3 事务边界

事务应围绕一个完整业务不变式划定边界。事务过大增加锁持有、日志和回滚成本，事务过小又可能让中间状态暴露给其他事务。跨服务操作不能仅依靠本地数据库事务，应采用可靠消息、补偿、Saga 或其他分布式事务方案。

预编译语句和参数绑定可以避免 SQL 注入，并减少重复解析。动态表名、排序字段和条件片段不能直接拼接用户输入，应使用白名单映射。
