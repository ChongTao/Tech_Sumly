# 2 事务、并发与锁

## 2.1 ACID

- 原子性：事务内操作全部成功或全部回滚。
- 一致性：事务前后满足约束和业务不变式。
- 隔离性：并发事务按隔离级别观察彼此结果。
- 持久性：提交结果在故障恢复后仍可重建。

ACID 是数据库提供的语义集合，不代表所有事务都自动满足业务正确性；应用仍需设计唯一性、状态流转和幂等规则。

## 2.2 隔离级别与异常

| 隔离级别 | 典型效果 | 代价/风险 |
| :--- | :--- | :--- |
| Read Uncommitted | 可能读取未提交数据 | 脏读，使用较少 |
| Read Committed | 只能读取已提交数据 | 同一事务两次读取可能不同 |
| Repeatable Read | 同一事务重复读取较稳定 | 可能出现幻读或需额外范围锁，依实现而定 |
| Serializable | 并发效果接近串行执行 | 冲突和等待最多 |

脏读是读取未提交修改；不可重复读是同一事务两次读取同一行结果不同；幻读是两次范围查询返回的行集合不同。MVCC 通过保存多个版本让读写减少互相阻塞，锁则用于保护写入和特定读写语义。

## 2.3 锁与死锁

行锁、页锁和表锁的粒度不同；共享锁允许并发读，排他锁保护写入。锁粒度越细并发通常越好，但锁管理和死锁检测成本更高。索引缺失可能使更新扫描并锁定大量记录，放大冲突。

死锁是循环等待，不是单纯的慢锁。数据库可能主动选择一个事务回滚，应用必须捕获死锁错误并在事务可重试时重新执行。所有事务按固定顺序访问多张表、缩短事务和建立合适索引可以降低死锁概率。

## 2.4 乐观与悲观并发

悲观并发在操作前加锁，适合冲突频繁且必须立即排他的场景；乐观并发在提交时检查版本号或更新时间，适合读多写少。乐观更新应检查受影响行数，更新为 0 时明确返回冲突，而不是静默覆盖。
