# 2 进程、线程与并发

## 2.1 进程与线程

进程是资源隔离和拥有地址空间的基本单位；线程是进程内执行指令的基本调度单位。同一进程的线程共享代码段、堆、打开的文件等资源，但各自拥有栈、寄存器和线程局部数据。

| 对象 | 主要特点 | 常见用途 |
| :--- | :--- | :--- |
| 进程 | 地址空间隔离，通信成本较高 | 服务隔离、故障边界、不同运行时 |
| 线程 | 共享进程资源，切换和通信通常更轻 | 并行计算、并发 I/O、后台任务 |
| 协程 | 由运行时或用户态调度，切换更轻 | 大量 I/O 等待、异步任务 |

线程共享资源提高效率，也引入数据竞争、死锁和错误传播风险。进程间通信可使用管道、共享内存、信号、socket 或消息队列；共享内存最快，但需要额外同步协议。

## 2.2 进程状态与调度

典型进程状态包括运行、就绪、阻塞和终止。任务等待磁盘、网络、锁或条件变量时会阻塞；事件完成后回到就绪队列。调度器在多个可运行任务之间选择下一个执行者。

常见调度目标：

- 吞吐量：单位时间完成更多任务。
- 延迟：缩短单个请求的等待和响应时间。
- 公平性：避免低优先级任务长期得不到运行。
- 实时性：在截止时间前完成任务。

时间片轮转适合交互式任务；优先级调度适合区分任务重要性；多级反馈队列会根据运行行为动态调整优先级。生产环境调整优先级前应先确认实际瓶颈，避免高优先级任务挤压系统关键线程。

## 2.3 同步原语

| 原语 | 作用 | 注意事项 |
| :--- | :--- | :--- |
| mutex | 保护互斥临界区 | 持锁时间要短，保持固定加锁顺序 |
| semaphore | 控制资源数量或传递事件 | 计数错误可能导致永久阻塞或超额使用 |
| condition variable | 等待某个条件成立 | 必须在循环中检查条件，防止虚假唤醒 |
| rwlock | 允许多个读者、单个写者 | 写多或临界区长时可能不如 mutex |
| atomic | 对单个变量提供原子操作 | 不能自动保护多个变量之间的不变式 |

同步的核心不是“让代码变慢”，而是维护共享状态的不变式。临界区应只包含必要操作；外部调用、磁盘 I/O 和长时间计算通常不应在锁内执行。

## 2.4 死锁与活锁

死锁通常需要同时满足互斥、占有且等待、不可剥夺和循环等待四个条件。常用预防方式是按全局顺序获取多把锁、使用带超时的尝试加锁、缩短持锁时间和减少共享状态。

排查死锁时记录锁的持有者、等待者、获取顺序和线程调用栈。不要通过无条件杀进程掩盖问题；应保留现场并修复锁顺序或事务边界。

## 2.5 进程退出与信号

父进程创建子进程后应处理子进程退出状态，否则可能留下僵尸进程。守护进程、服务管理器和容器运行时还应正确转发终止信号，使应用有机会停止接收新请求、完成必要清理并退出。

优雅关闭通常包括：停止接收流量、等待在途请求、停止后台任务、刷新日志和指标、释放资源，并设置最终超时。清理逻辑必须幂等，避免重复信号造成异常。
