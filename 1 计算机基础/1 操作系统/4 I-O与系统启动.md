# 4 I/O 与系统启动

## 4.1 I/O 模型

阻塞 I/O 会让线程等待操作完成；非阻塞 I/O 立即返回，应用需要再次检查；I/O 多路复用允许一个线程等待多个描述符；异步 I/O 则由系统在完成后通知应用。多路复用常用于网络服务器，但它并不自动解决 CPU 计算、线程安全和背压问题。

同步是调用方等待结果，异步是提交后由回调、Future 或事件通知结果；阻塞与非阻塞描述调用是否立即让出线程。两组概念经常组合使用，不能混为一谈。

## 4.2 网络 I/O 与背压

高并发服务需要限制连接数、请求体大小、缓冲区和并发任务数。生产者速度超过消费者时必须施加背压，例如限制队列长度、暂停读取或拒绝新任务；无限队列只会把问题转化为内存增长和更长延迟。

超时至少应区分连接、读、写、整个请求和空闲连接超时。重试只适用于明确的瞬时错误，并配合指数退避、随机抖动和最大次数；对非幂等操作盲目重试可能造成重复写入。

## 4.3 启动流程

典型计算机启动流程为固件初始化硬件，选择启动设备，加载引导程序，引导程序加载内核和初始文件系统，内核初始化内存、调度器和设备后启动用户空间的第一个进程，最后由服务管理器启动系统服务。

服务启动应明确依赖关系、就绪条件、失败重试和关闭顺序。仅判断进程存在不等于服务可用；更可靠的健康检查应验证端口、关键依赖和最小业务请求。

## 4.4 日志与可观测性

操作系统和服务日志应包含时间、进程/线程、级别、错误码和关联请求标识。日志轮转需要同时设置按大小、按时间、保留数量和压缩策略，避免日志占满磁盘。

排查系统问题时结合：

- 指标：CPU、内存、磁盘、网络、文件描述符和上下文切换。
- 日志：服务错误、内核告警、启动失败和资源耗尽。
- 追踪与剖析：调用链、线程栈、系统调用和 I/O 延迟。

指标用于发现趋势，日志用于解释事件，剖析用于定位热点；三者应使用统一时间和实例标识关联。
