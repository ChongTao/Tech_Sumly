# 1 操作系统概述

操作系统是管理计算机硬件资源并向应用提供运行环境的系统软件。它在应用与处理器、内存、磁盘、网络设备之间提供抽象、隔离、调度和保护。

## 1.1 核心职责

| 职责 | 说明 |
| :--- | :--- |
| 进程管理 | 创建、调度、切换和回收进程与线程 |
| 内存管理 | 分配虚拟地址空间、映射物理内存并进行回收 |
| 文件与存储管理 | 用文件、目录和权限抽象持久化设备 |
| 设备管理 | 通过驱动和 I/O 子系统访问磁盘、网卡等设备 |
| 安全与隔离 | 提供用户态/内核态、权限、沙箱和资源限制 |
| 网络服务 | 提供 socket 等通信抽象和协议栈接口 |

## 1.2 用户态与内核态

应用通常运行在用户态，不能直接执行特权指令或访问任意物理地址。需要访问文件、创建进程、申请内存等资源时，应用通过系统调用进入内核态。内核完成校验和操作后再返回用户态。

系统调用是稳定的能力边界；库函数（如 C 标准库、语言运行时）可能进一步封装系统调用。一次调用涉及用户态/内核态切换、参数检查和调度，设计高频 I/O 时应减少不必要的调用次数。

## 1.3 中断、异常与上下文切换

- 中断通常由外部设备异步触发，例如网卡收到数据或定时器到期。
- 异常由当前指令执行引起，例如缺页异常、除零或非法访问。
- 系统调用是应用主动请求内核服务的一种受控入口。
- 上下文切换需要保存和恢复寄存器、地址空间等状态，会带来调度和缓存开销。

定时器中断让内核可以周期性抢占运行中的任务；I/O 中断则允许设备完成后唤醒等待任务。高并发系统需要区分 CPU 消耗、锁竞争和 I/O 等待，不能只看进程总运行时间。

## 1.4 资源隔离与容器

容器共享宿主机内核，通过 namespace 隔离进程、网络、挂载点等视图，通过 cgroup 限制 CPU、内存、进程数和 I/O 等资源。容器不是完整虚拟机：它通常不能运行与宿主机不兼容的内核，隔离强度也依赖内核配置和运行时安全策略。

虚拟机在硬件或 hypervisor 层隔离操作系统，边界更强但资源开销更大。选择容器或虚拟机时，应结合隔离要求、启动速度、内核需求和运维方式评估。

## 1.5 常用排查思路

1. 先确认进程是否存活、退出码和启动参数。
2. 判断资源瓶颈属于 CPU、内存、磁盘 I/O、网络或锁等待。
3. 结合系统日志、进程指标、线程状态和调用栈定位具体任务。
4. 变更前保留现场，变更后用相同指标验证结果。

不要仅通过“CPU 高”或“内存高”下结论：CPU 高可能来自正常吞吐、死循环或锁自旋；内存高可能是缓存、堆增长、页缓存或内存泄漏。
