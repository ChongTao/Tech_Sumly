# 3 排序、查找与算法工程

## 3.1 排序

| 算法 | 平均时间 | 额外空间 | 稳定性 | 适用特点 |
| :--- | :--- | :--- | :--- | :--- |
| 插入排序 | `O(n²)` | `O(1)` | 稳定 | 小规模或近乎有序数据 |
| 归并排序 | `O(n log n)` | `O(n)` | 稳定 | 需要稳定排序、外部排序 |
| 快速排序 | `O(n log n)` | `O(log n)` 平均 | 不稳定 | 内存排序常用，需避免最坏划分 |
| 堆排序 | `O(n log n)` | `O(1)` | 不稳定 | 需要稳定上界空间 |
| 计数/基数排序 | 与值域相关 | 与值域相关 | 可稳定 | 整数或固定格式键 |

稳定排序能保持相等元素原有相对顺序。多字段排序可以先按低优先级稳定排序，再按高优先级排序，也可以直接使用复合比较器。选择算法时应结合数据规模、是否需要稳定性、内存限制和库实现，不要只依据理论复杂度。

## 3.2 查找与二分

二分查找要求数据按比较规则有序，并保持循环不变量。计算中点应避免整数溢出，例如使用 `left + (right-left)/2`。边界问题通常集中在闭区间/半开区间混用、找不到元素时的返回值和重复元素的第一个/最后一个位置。

前缀树适合字符串前缀查找，空间消耗可能很大；倒排索引适合文本关键词检索；布隆过滤器使用多个哈希位判断“可能存在”或“一定不存在”，存在误判但没有漏判，通常用于减少无效查询。

## 3.3 动态规划与贪心

动态规划适用于存在重叠子问题和最优子结构的问题。设计步骤是确定状态、状态转移、初始值、遍历顺序和答案位置，并检查状态空间是否可压缩。

贪心算法每一步选择当前看起来最优的方案，只有在能证明贪心选择性质和最优子结构时才能保证全局最优。没有证明时应通过反例、穷举或动态规划验证，而不能凭直觉使用。

## 3.4 工程实践

- 先定义输入约束、异常行为和正确性不变量，再选择算法。
- 使用边界、空输入、重复值、极端规模和随机数据测试。
- 对算法做基准测试时固定数据集、预热方式、编译选项和内存环境。
- 关注算法外的成本：序列化、网络、磁盘、锁竞争和内存分配常常更昂贵。
- 对不可信输入限制时间、空间和递归深度，避免算法复杂度攻击。
