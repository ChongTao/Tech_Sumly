# 2 树、图与哈希

## 2.1 树

二叉搜索树要求左子树键小于节点、右子树键大于节点；退化时查找会从 `O(log n)` 下降为 `O(n)`。AVL 树和红黑树通过旋转保持近似平衡，适合有序查找、范围查询和动态更新。

堆是满足局部序关系的完全二叉树，插入和删除堆顶通常为 `O(log n)`，构建堆可以是 `O(n)`。B/B+ 树适合磁盘和数据库索引：节点较宽、树高较低，B+ 树叶子节点有序连接，便于范围扫描。

## 2.2 图

图由顶点和边组成，可表示依赖关系、网络拓扑和路线。邻接矩阵适合顶点少且查询边是否存在频繁的场景，邻接表适合稀疏图。

| 问题 | 常见算法 | 复杂度/注意 |
| :--- | :--- | :--- |
| 无权最短路 | BFS | 邻接表通常为 `O(V+E)` |
| 非负权最短路 | Dijkstra | 不能处理负权边 |
| 可含负权最短路 | Bellman-Ford | 可检测负环，复杂度较高 |
| 全源最短路 | Floyd-Warshall | `O(V³)`，适合规模较小 |
| 最小生成树 | Kruskal / Prim | 用于连通代价最小的无向图 |
| 拓扑排序 | 入度法 / DFS | 仅适用于有向无环图 |

遍历图时要记录访问状态，递归 DFS 还要关注调用栈深度。依赖图存在环时不能直接进行拓扑排序，应先报告环路或使用强连通分量分析。

## 2.3 哈希表

哈希表通过哈希函数把键映射到桶，平均查找、插入和删除接近 `O(1)`。冲突处理可以使用链地址法或开放寻址法；装载因子过高会增加冲突，通常需要扩容和重新分布。

哈希函数应尽量均匀，键的哈希值和相等判断必须一致。可变对象作为键时，插入后改变参与哈希的字段会导致无法查找。哈希表不保证有序，若需要范围查询或稳定顺序，应使用树结构或额外维护顺序索引。

一致性哈希通过有限数量的虚拟节点减少节点增删带来的重新分配，常用于缓存和分片。但它不自动解决热点、数据复制、故障恢复和一致性问题。
