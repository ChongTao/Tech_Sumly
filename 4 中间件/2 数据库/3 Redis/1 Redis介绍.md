# 1 Redis介绍

Redis 是一个基于内存的数据结构存储系统，常被用作缓存、分布式锁、计数器、排行榜、消息队列和会话存储。它的特点是读写性能高、数据结构丰富、支持持久化，并且具备主从复制、哨兵和集群能力。

和传统关系型数据库相比，Redis 更适合承接高并发、低延迟、热点访问明显的场景，但通常不负责复杂关联查询，也不适合作为唯一核心数据存储。

## 1.1 Redis 能做什么

- 缓存热点数据，减轻数据库压力
- 维护计数器，例如点赞数、访问量、库存余量
- 做排行榜，例如积分榜、热度榜
- 保存会话数据，例如登录态、验证码
- 实现分布式锁和幂等控制
- 构建轻量消息队列、延迟任务、发布订阅

## 1.2 Redis 为什么快

Redis 性能高，核心原因通常有以下几点：

- 基于内存访问，避免了磁盘随机 I/O
- 单线程执行命令，避免了大量锁竞争和线程切换
- 数据结构设计紧凑，很多操作的时间复杂度较低
- 网络模型高效，适合处理大量短连接和高频请求
- 常用命令通常是 O(1) 或接近 O(1)

Redis 单线程指的是命令执行模型以单线程为主，不代表整个进程只有一个线程。较新的 Redis 版本在网络读写等环节可以使用多线程，但命令执行本身仍然强调串行处理。

## 1.3 常见数据结构

### String

最基础的数据类型，可以保存字符串、整数、浮点数，也常被用于缓存对象序列化结果、计数器和分布式锁。

常见命令：

```bash
SET user:1 "tom"
GET user:1
INCR page:view:1001
SET lock:order:1 token NX EX 30
```

### Hash

适合保存对象的多个字段，例如用户信息、商品信息。相比直接保存整个 JSON，按字段更新更方便。

```bash
HSET user:1 name tom age 18 city shanghai
HGET user:1 name
HGETALL user:1
```

### List

底层是按顺序组织的列表，适合消息队列、任务队列、时间线等场景。

```bash
LPUSH queue:order order1 order2
RPOP queue:order
LRANGE queue:order 0 -1
```

### Set

无序且元素唯一，适合去重、标签集合、共同好友等场景。

```bash
SADD user:1:tags java redis mysql
SMEMBERS user:1:tags
SINTER user:1:tags user:2:tags
```

### ZSet

有序集合，元素唯一且带分值，特别适合排行榜、优先级队列、延迟任务。

```bash
ZADD rank:game 100 user1 88 user2 95 user3
ZRANGE rank:game 0 -1 WITHSCORES
ZREVRANGE rank:game 0 9 WITHSCORES
```

### Bitmap、HyperLogLog、Geo、Stream

- Bitmap 适合签到、布尔状态统计
- HyperLogLog 适合基数统计，例如 UV 估算
- Geo 适合地理位置查询
- Stream 适合可回溯的消息流场景

## 1.4 Redis 的持久化

Redis 主要有两种持久化方式：RDB 和 AOF。

### RDB

RDB 会在某个时间点把内存中的数据生成快照并写入磁盘。

优点：

- 文件紧凑，适合备份和恢复
- 恢复速度通常较快
- 对运行时性能影响相对可控

缺点：

- 两次快照之间如果机器故障，可能丢失一段时间的数据

### AOF

AOF 会记录写命令，通过重放命令恢复数据。

优点：

- 数据更完整，丢失窗口通常更小
- 可根据刷盘策略平衡性能和可靠性

缺点：

- 文件通常比 RDB 更大
- 恢复速度一般慢于 RDB

### 如何选择

- 更关注恢复速度和备份文件体积时，可以优先考虑 RDB
- 更关注数据完整性时，可以优先考虑 AOF
- 生产环境里常见做法是同时开启 RDB 和 AOF

## 1.5 过期删除与内存淘汰

Redis 支持给 key 设置过期时间，例如：

```bash
SET code:login:13800000000 123456 EX 300
TTL code:login:13800000000
```

Redis 处理过期 key 通常结合两种方式：

- 惰性删除：访问 key 时发现已过期，再删除
- 定期删除：后台周期性抽样检查并清理过期 key

当内存达到上限后，还需要使用淘汰策略。常见策略有：

- `noeviction`：不淘汰，直接返回写入失败
- `allkeys-lru`：从所有 key 中淘汰最近最少使用的数据
- `allkeys-lfu`：从所有 key 中淘汰最不经常使用的数据
- `volatile-lru`：只在设置了过期时间的 key 中做 LRU 淘汰
- `volatile-ttl`：优先淘汰更快过期的 key

如果 Redis 主要用于缓存，通常会考虑 `allkeys-lru` 或 `allkeys-lfu`。

## 1.6 Redis 高可用

### 主从复制

Redis 可以通过主从复制把主节点数据同步到从节点。

作用：

- 读写分离，降低主节点读压力
- 提升可用性和数据冗余能力

限制：

- 从节点通常有复制延迟
- 主节点故障后，仅靠主从复制不能自动完成故障转移

### Sentinel

哨兵模式用于监控 Redis 主从节点，并在主节点故障时自动完成故障转移。

它主要解决三个问题：

- 监控 Redis 实例是否正常
- 自动选主并切换
- 通知客户端新的主节点地址

### Cluster

Redis Cluster 面向更大规模的数据量和吞吐量，采用分片方式把数据分散到多个节点上。

特点：

- 数据分片，支持水平扩展
- 每个分片可带副本，提高可用性
- 适合大容量、高并发场景

## 1.7 Redis 常见缓存问题

### 缓存穿透

请求访问的数据既不在缓存中，也不在数据库中，导致请求每次都打到数据库。

常见方案：

- 缓存空值，并设置较短过期时间
- 对非法参数做校验
- 使用布隆过滤器拦截明显不存在的 key

### 缓存击穿

某个热点 key 在失效瞬间，大量请求同时访问数据库。

常见方案：

- 对热点 key 不设置过期时间，转为主动更新
- 使用互斥锁或单飞机制，只让一个线程回源
- 提前刷新热点数据

### 缓存雪崩

大量 key 在同一时间集中失效，导致数据库压力骤增。

常见方案：

- 给过期时间增加随机值，打散失效时刻
- 做多级缓存和降级兜底
- 对热点数据预热
- 限流和熔断，保护后端数据库

## 1.8 Redis 分布式锁

Redis 常被用来实现轻量分布式锁，常见写法如下：

```bash
SET lock:order:1001 requestId NX EX 30
```

这条命令的含义是：

- `NX` 表示只有 key 不存在时才加锁成功
- `EX 30` 表示 30 秒后自动过期，避免死锁

释放锁时不能直接 `DEL`，而要先确认锁的持有者是自己，通常要通过 Lua 脚本保证“比较并删除”的原子性。

Redis 锁适合大多数工程场景，但如果业务对一致性要求极高，需要认真评估时钟漂移、主从切换和锁续期等问题。

## 1.9 常见使用建议

- key 命名要有业务前缀，例如 `user:1:profile`
- 控制 value 大小，避免大 key 影响延迟和迁移
- 热点 key 需要重点监控
- 缓存数据要设置合理过期时间，避免长期脏数据
- 不要把 Redis 当作关系型数据库使用
- 对重要数据要明确持久化和灾备策略
