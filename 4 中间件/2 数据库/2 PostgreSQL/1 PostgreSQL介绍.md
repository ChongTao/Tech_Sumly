# 1 PostgreSQL 介绍

PostgreSQL 是功能完善的开源对象关系型数据库。除标准关系模型和事务外，它还提供丰富的数据类型、MVCC、JSONB、全文检索、扩展机制和地理空间能力，适合复杂查询、数据分析及需要灵活数据模型的业务。

## 1.1 核心特点

- 支持 ACID 事务、MVCC 和多种事务隔离级别。
- 数据类型丰富，包含数组、`JSONB`、范围类型、UUID、网络地址和时间类型。
- 支持 B-tree、GIN、GiST、BRIN、Hash 等索引类型。
- 支持窗口函数、CTE、物化视图、分区表和逻辑复制。
- 通过扩展机制增强能力，例如 PostGIS 提供空间数据处理。

## 1.2 基本概念

| 概念 | 说明 |
| :--- | :--- |
| cluster | 由一个 PostgreSQL 服务进程管理的数据目录和多个数据库 |
| database | 独立的数据库，客户端连接后在其中操作对象 |
| schema | 命名空间，用于组织表、视图、函数等对象 |
| table | 表，保存结构化数据 |
| role | 角色，可作为用户或用户组并拥有权限 |
| WAL | 预写式日志，用于崩溃恢复和复制 |
| vacuum | 清理过期行版本并维护统计信息的机制 |

## 1.3 MVCC 与 VACUUM

PostgreSQL 采用多版本并发控制（MVCC）。更新或删除不会立刻覆盖旧行版本，而是生成新版本或标记旧版本失效，使读写通常可以并发进行。

旧版本需要由 `VACUUM` 回收。默认的 autovacuum 会自动处理大部分场景；如果表更新频繁且 autovacuum 不及时，可能产生表膨胀、统计信息过期或事务 ID 风险。因此生产环境应监控 autovacuum、慢查询和表膨胀情况。

## 1.4 索引要点

- B-tree 是默认索引，适合等值、范围、排序查询。
- GIN 适合 `JSONB`、数组和全文检索等包含关系查询。
- GiST 适合范围、空间和相似度等可扩展查询。
- BRIN 适合按物理顺序高度相关的大表字段，如持续增长的时间列。
- 使用 `EXPLAIN (ANALYZE, BUFFERS)` 基于实际执行数据评估查询计划。

## 1.5 使用建议

- 业务对象显式使用 schema，例如 `app.orders`，避免依赖不确定的 `search_path`。
- 金额使用 `numeric`，业务主键可使用 `bigint generated ... as identity` 或 UUID。
- 长事务会阻碍旧版本回收，应避免在事务中等待用户输入或执行耗时外部操作。
- 对 JSONB 查询建立匹配查询方式的 GIN 或表达式索引，不能只因字段是 JSON 就盲目建索引。
- 备份可使用 `pg_dump`；物理备份、WAL 归档与恢复演练用于更严格的恢复目标。
