# 1 MongoDB介绍

MongoDB 是面向文档的 NoSQL 数据库，以 BSON（二进制文档格式）表示文档，适合半结构化数据、高并发读写和需要快速演进的数据模型。相比传统关系型数据库，MongoDB 更强调面向查询模式的数据建模和水平扩展能力。

MongoDB 使用 BSON 编码文档，并通过 BSON 文档与客户端交换数据；数据文件中的文档、索引和元数据则由存储引擎按其内部结构组织。因此，BSON 是 MongoDB 的文档编码和类型系统，磁盘文件不是 BSON 文档的简单拼接。

核心特点：

- 文档模型，适合对象化和嵌套结构数据
- Schema 灵活，字段扩展成本低
- 支持副本集，实现高可用
- 支持分片，实现横向扩展
- 索引能力丰富，支持复合索引、唯一索引、TTL 索引等
- 支持聚合管道，适合统计和数据加工

## 1.1 基本概念

MongoDB 使用集合组织文档，每个文档由键值对组成。

- Database：数据库，类似于关系型数据库中的数据库。

  如果在操作中未指定数据库，使用默认test数据库，数据库存储在data目录中。

- Collection：集合，类似关系型数据库中的表。

  存储在同一数据库中的一组文档。它类似于关系型数据库中的表，其中集合中的每个文档相当于表中的一行。但集合没有固定的模式。

- Document：文档，类似关系型数据库中的一行记录

  MongoDB 的文档不需要设置相同的字段，并且相同的字段不需要相同的数据类型。

- Field：字段，类似列

- Index：索引

| SQL 概念 | MongoDB 概念 | 说明 |
| :--- | :--- | :--- |
| database | database | 数据库 |
| table | collection | 集合 |
| row | document | 文档 |
| column | field | 字段 |
| index | index | 索引 |
| primary key | `_id` | 默认主键 |

## 1.2 常见 BSON 数据类型

| BSON 类型 | 描述 |
| :--- | :--- |
| String | UTF-8 字符串。 |
| Boolean | 布尔值。 |
| Null | 显式空值；字段不存在与字段值为 `null` 是两种不同状态。 |
| Document | 嵌套文档，由字段和值组成。 |
| Array | 有序数组，可包含不同 BSON 类型的值。 |
| Int32 / Int64 | 32 位 / 64 位有符号整数，整数宽度由 BSON 类型明确区分。 |
| Double | 64 位双精度浮点数。 |
| Decimal128 | 128 位十进制浮点数，适用于需要十进制精度的数值。 |
| Date | 64 位有符号整数，表示自 Unix 纪元以来的毫秒数；表示时间点，本身不保存时区名称。 |
| Timestamp | 由秒数和递增序号组成的 BSON 类型，常用于 MongoDB 内部时间戳和 oplog，不应当作通用业务日期类型。 |
| ObjectId | 12 字节标识符，常用作文档默认的 `_id` 值。 |
| Binary | 二进制数据，并带有子类型标记。 |
| Regular Expression | 正则表达式及其选项。 |
| MinKey / MaxKey | 用于比较的特殊边界值，分别低于或高于其他 BSON 类型。 |

## 1.3 BSON 与 JSON

### BSON 的结构

BSON（Binary JSON）是面向文档的二进制编码格式，与 JSON 一样可以表达字段、嵌套对象和数组，但它不是把 JSON 文本压缩成二进制。一个 BSON 文档以长度信息开头，由带类型标记的字段和值组成，并以结束标记收尾；数组也按 BSON 文档编码，字段名使用连续的数字序号。明确的长度和类型信息使驱动与服务器可以识别字段边界及值的类型。

MongoDB 驱动负责在应用语言的对象与 BSON 之间转换，客户端和服务器之间的文档也以 BSON 编码传输。持久化时，存储引擎还会管理数据页、索引、元数据和压缩等，因此不能通过直接查看 MongoDB 数据文件来阅读 BSON 文档。

### BSON 和 JSON 的主要区别

| 对比项 | JSON | BSON |
| :--- | :--- | :--- |
| 表示形式 | UTF-8 文本，可直接阅读 | 二进制编码，需要驱动或解析工具读取 |
| 类型系统 | 标准类型包括对象、数组、字符串、数字、布尔值和 `null`；没有独立的日期、二进制、ObjectId 或整数宽度类型 | 除常见基本类型外，还包含 Date、Binary、ObjectId、Decimal128、Int32、Int64 等类型 |
| 解析特点 | 文本格式，通用性强，适合人工检查和系统间交换 | 长度和类型信息便于识别字段边界并保留值类型 |
| 大小与性能 | 具体取决于数据和实现 | 有字段名、类型标记等编码开销，不一定比 JSON 更小，也不保证所有场景都更快 |

例如，MongoDB Shell 中可以这样表示一个文档：

```javascript
{
  _id: ObjectId("65f000000000000000000001"),
  age: NumberInt(18),
  createdAt: ISODate("2026-10-13T00:00:00Z")
}
```

这里的 Shell 写法用于展示 BSON 类型，实际交换和持久化的是 BSON 编码。若把这些值直接写成普通 JSON 字符串和数字，`ObjectId`、日期以及整数宽度等类型信息不会由标准 JSON 保留；需要通过应用约定转换，或使用 MongoDB Extended JSON 表达 BSON 类型。MongoDB 单个 BSON 文档的大小上限为 16 MiB，建模时应将文档及嵌套数组的大小考虑在内。
