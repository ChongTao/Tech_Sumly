# 1 缓存与存储介绍

缓存通过保存可重建或可接受短暂过期的数据降低后端压力；存储负责长期、可靠地保存权威数据。缓存不是数据库备份，也不应成为唯一数据来源，除非系统明确接受丢失并具备重建机制。

## 1.1 缓存模式

| 模式 | 读写方式 | 注意事项 |
| :--- | :--- | :--- |
| Cache-aside | 应用先读缓存，未命中读库后回填 | 最常见，需处理击穿和一致性 |
| Read-through | 缓存层负责回源 | 简化应用，但依赖缓存能力 |
| Write-through | 写缓存同时同步后端 | 读一致性好，写延迟较高 |
| Write-behind | 先写缓存，异步落后端 | 吞吐高但存在丢失和顺序风险 |

## 1.2 常见风险

缓存穿透是大量请求访问不存在的键，可用参数校验、空值短 TTL 或布隆过滤器缓解；缓存击穿是热点键失效瞬间大量回源，可用互斥刷新、逻辑过期或预热；缓存雪崩是大量键同时失效，可使用 TTL 抖动和分批刷新。

缓存更新与数据库写入存在竞态。根据业务选择先更新库再删除缓存、延迟双删、消息失效或版本化键，并用对账或重建修复极端不一致。缓存值要设置大小、序列化版本和最大 TTL，避免大对象和永久键耗尽内存。

## 1.3 对象与块存储

对象存储适合图片、视频、备份和大文件，通过对象键和元数据访问；应用应使用临时授权 URL、校验内容类型和大小，并考虑分片上传、断点续传、生命周期和版本控制。块存储提供类似磁盘的块设备，适合数据库和文件系统，但需要关注 IOPS、吞吐、快照一致性和故障恢复。
