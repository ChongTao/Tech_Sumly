# 1 线程池与锁

## 1.1 线程池

线程池通过复用工作线程减少创建成本，并限制并发任务数。核心参数包括核心线程数、最大线程数、任务队列容量、空闲回收时间和拒绝策略。

CPU 密集型任务通常按 CPU 核数附近设置并发；I/O 密集型任务可适当提高，但必须受下游连接、文件描述符和内存限制。队列无限增长会隐藏处理能力不足，最终造成延迟和内存问题。

拒绝策略应与业务明确匹配：快速失败、调用方执行、丢弃低优先级任务或持久化到消息队列。线程池应按用途隔离，避免慢 I/O 或批处理耗尽请求线程。

## 1.2 锁设计

锁保护的是共享状态不变式，不是任意代码。保持固定加锁顺序，缩短临界区，避免在锁内执行网络、磁盘和未知回调。读写锁只有在读多写少且临界区合适时才可能有收益。

锁竞争要通过等待时间、持有时间、阻塞线程和调用栈定位。自旋锁只适合极短临界区且 CPU 资源充足的场景；带超时的锁可以避免无限等待，但超时后的业务补偿仍需设计。
