# 1 压测与容量规划

压测用于观察系统在指定负载、数据规模和故障条件下的吞吐、延迟、错误率和资源边界。压测模型应接近真实请求比例、读写比例、数据分布、连接行为和下游依赖。

## 1.1 压测类型

| 类型 | 目的 |
| :--- | :--- |
| 基准测试 | 对比单个实现、接口或版本 |
| 负载测试 | 验证目标并发和吞吐下的稳定性 |
| 压力测试 | 找出超过容量后的退化方式 |
| 稳定性测试 | 长时间运行发现泄漏和积压 |
| 故障测试 | 验证依赖、节点和网络异常下的降级 |

## 1.2 容量模型

容量规划至少估算峰值 QPS、并发连接、响应大小、CPU、内存、磁盘 IOPS、网络带宽、数据库连接和消息积压。为滚动发布、实例故障和流量突发预留余量，不能把 100% 资源利用率当作目标。

测试结果应记录版本、配置、机器规格、数据量、压测工具、流量模型和瓶颈证据。压测环境与生产差异很大时，结论只能用于趋势比较，不能直接承诺生产容量。
