# 1 HTTP 基础与实践

HTTP 由请求方法、目标、首部和消息体组成，响应由状态码、首部和消息体组成。资源接口应保持方法语义、状态码和错误结构稳定。

## 1.1 状态码

| 类别 | 典型状态码 | 含义 |
| :--- | :--- | :--- |
| 2xx | 200、201、202、204 | 成功、创建、已接受异步处理、无内容 |
| 3xx | 301、302、304 | 重定向或使用缓存 |
| 4xx | 400、401、403、404、409、429 | 请求错误、未认证、无权限、未找到、冲突、限流 |
| 5xx | 500、502、503、504 | 服务内部错误、网关错误、暂不可用、下游超时 |

401 表示缺少或无效身份，403 表示身份存在但没有权限。业务错误应有稳定错误码、消息和可选详情，不能只依赖 HTTP 状态码表达所有业务语义。

## 1.2 缓存与条件请求

`Cache-Control`、`ETag`、`Last-Modified` 和 `If-None-Match` 可以减少重复传输。缓存公共数据时要确认权限和租户不会被缓存键混淆；敏感响应默认不应被共享缓存保存。

## 1.3 重试与幂等

GET、HEAD、OPTIONS 通常可安全重试，但仍要考虑服务端副作用；POST 超时不能直接判定未执行。创建资源可使用 `Idempotency-Key`，服务端保存请求结果或状态，确保重复请求返回一致结果。

## 1.4 安全与限制

服务必须限制请求体、首部、上传文件、并发和处理时间。TLS 终止在代理时，要正确校验转发首部。输入验证、输出转义、CORS、CSRF、认证、授权和敏感信息脱敏应按接口风险配置。
