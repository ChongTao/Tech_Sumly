# 1 TCP 与 UDP 实践

TCP 提供可靠有序字节流，UDP 提供无连接数据报。TCP 解决传输可靠性和拥塞控制，但不保留应用消息边界；UDP 不保证交付、顺序和去重，可靠性需要应用协议自行实现。

## 1.1 TCP 应用协议

TCP 服务必须定义消息帧，例如固定长度、长度前缀、分隔符或自描述编码。读取接口可能返回半条消息，也可能一次返回多条消息，应用要循环解析并保留未完成字节。

连接建立成功只表示传输层可达，不表示应用就绪。应用层应发送协议握手或健康请求验证版本、认证和业务状态。关闭连接时要处理半关闭、读到 EOF 和在途请求。

## 1.2 UDP 应用协议

UDP 报文需要设置最大大小，避免分片和路径 MTU 问题。若需要可靠性，可加入序列号、确认、重传、去重、乱序缓冲和过期时间；但不要重复实现已有成熟协议而忽略拥塞控制。

## 1.3 排障指标

关注连接建立耗时、RTT、重传、丢包、发送/接收窗口、TIME_WAIT、连接数、读写阻塞和应用队列。抓包时注意 TLS 和加密协议只能看到包级信息，应用语义需要结合日志和 trace ID。
