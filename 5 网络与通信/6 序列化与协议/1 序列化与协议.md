# 1 序列化与协议

序列化把内存对象转换为可传输或持久化的字节，反序列化再恢复为对象。协议除了数据格式，还应定义消息边界、版本、错误、认证、压缩和超时语义。

## 1.1 格式选择

| 格式 | 优点 | 代价 |
| :--- | :--- | :--- |
| JSON | 可读、生态广、调试方便 | 体积较大、类型约束弱 |
| Protobuf | 体积小、速度快、契约明确 | 需要 schema 和代码生成 |
| Avro | schema 演进和流式生态较好 | 依赖 schema 管理 |
| MessagePack | 比 JSON 紧凑、使用方便 | 跨语言语义和工具依赖实现 |

## 1.2 兼容性

新增字段应提供默认行为，读取端忽略未知字段；不要复用旧字段编号或改变字段含义。枚举要保留未知值处理，时间、金额、精度、字符编码和空值语义必须明确。

## 1.3 安全与性能

反序列化前限制消息大小、嵌套深度、数组长度和压缩后膨胀比，防止资源耗尽。不要反序列化不可信对象类型或执行任意代码。压缩适合网络带宽受限场景，但会消耗 CPU，应通过基准测试决定压缩级别。

协议演进要有 schema 注册、兼容性检查、灰度发布和废弃计划。日志中记录协议版本和消息 ID，但不要直接记录完整敏感载荷。
