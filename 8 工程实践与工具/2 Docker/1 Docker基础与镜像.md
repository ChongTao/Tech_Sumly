# 1 Docker 基础与镜像

Docker 镜像是分层的只读文件系统，容器是在镜像上运行的隔离进程。容器退出后，容器可写层可能丢失；持久化数据应使用 volume、绑定挂载或外部存储。

## 1.1 镜像构建

Dockerfile 应使用可信且固定版本的基础镜像，减少层和无用文件，利用构建缓存，并通过 `.dockerignore` 排除源码仓库、密钥和构建产物。多阶段构建可以把编译环境与运行环境分开。

容器应以非 root 用户运行，明确 `CMD`/`ENTRYPOINT`、端口、健康检查和时区。镜像中不应写入环境密钥；通过运行时配置注入。发布前扫描漏洞并生成可追溯的镜像标签或 digest。

## 1.2 资源与网络

容器的 CPU、内存、进程数和文件系统限制要与服务并发匹配。设置内存上限后，JVM、线程池和缓存也要按容器限制规划。容器网络中的服务地址应使用服务发现或编排平台 DNS，不要依赖固定 IP。
