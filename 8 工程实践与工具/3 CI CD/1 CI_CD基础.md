# 1 CI/CD 基础

持续集成（CI）在代码变更后自动执行构建、测试、静态检查和安全扫描；持续交付（CD）把通过验证的制品部署到环境；持续部署则进一步自动发布到生产。

## 1.1 流水线阶段

典型流水线为依赖安装、格式和静态检查、单元测试、构建制品、集成测试、镜像扫描、部署测试环境、验收和生产发布。制品应只构建一次，后续环境提升使用同一制品，避免“各环境重新编译”。

流水线凭据遵循最小权限，敏感变量不打印到日志。构建环境应尽量固定版本并缓存可验证的依赖；第三方脚本和 Action 需要锁版本并审查来源。

## 1.2 发布策略

滚动发布逐步替换实例；蓝绿发布在两套环境间切换；金丝雀发布先给小比例流量。每种策略都要有健康检查、指标门禁、暂停条件和快速回滚。数据库变更应采用向后兼容的 expand-and-contract。
