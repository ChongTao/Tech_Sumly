# 1 一致性与共识

## 1.1 副本一致性

同步复制通常在多个副本确认后才返回，数据丢失风险低但延迟和可用性成本高；异步复制先向主副本确认，吞吐和延迟较好，但故障切换可能丢失最近写入。读副本延迟会导致读到旧值，应用要按场景选择强读、因果读或最终一致读。

## 1.2 共识问题

共识协议让多个节点在存在故障和网络延迟时，就某个值或日志顺序达成一致。它通常包含领导者选举、日志复制、提交和成员变更。Raft 以易理解为目标，常见实现包括选主、任期、日志匹配和多数派提交。

多数派不能解决所有问题：如果多数节点不可用，系统可能无法提交；脑裂时必须拒绝少数派写入；成员变更必须使用安全的联合配置或等价机制。客户端还要处理领导者变化、重试和重复提交。

## 1.3 CAP 与 PACELC

CAP 讨论网络分区发生时，在一致性和可用性之间的选择，不能被简单理解为“系统平时只能二选一”。PACELC 进一步指出，即使没有分区，也要在延迟和一致性之间权衡。选型时应以业务读写语义、故障目标和数据价值为准。
