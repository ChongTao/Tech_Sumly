# 1 分布式事务

分布式事务涉及多个数据库、服务或资源管理器，难点在于参与者不能共享单机事务日志。设计前应优先考虑业务拆分、异步事件和补偿，而不是直接引入强一致协议。

## 1.1 常见方案

| 方案 | 特点 | 适用与风险 |
| :--- | :--- | :--- |
| 两阶段提交（2PC） | 先准备、后提交 | 强一致但协调器和锁等待影响可用性 |
| TCC | Try/Confirm/Cancel 业务补偿 | 控制精细，但开发成本高 |
| Saga | 一系列本地事务及逆向补偿 | 长流程适用，补偿不一定等价回滚 |
| 本地消息表/Outbox | 本地事务写业务和待发送事件 | 最终一致、可靠且易落地 |
| 可靠事件与状态机 | 通过事件推进业务状态 | 需要幂等、重试和对账 |

## 1.2 实践原则

每个步骤应有业务唯一号、状态、超时、重试次数和补偿动作。补偿操作必须幂等，且要考虑“原操作成功但响应丢失”的情况。不要把网络超时直接当作失败，先查询下游状态或通过对账确认。

事务日志、消息、状态转移和人工处理都应可观测。对账任务用于发现长期不一致，不应成为正常流程的唯一一致性保障。
