# 1 分布式锁

分布式锁用于让多个进程或节点在一段时间内互斥执行某项操作。它适合保护短临界区，不适合替代数据库约束、幂等设计或长时间持有的业务事务。

## 1.1 必要语义

- 互斥：同一资源通常只有一个持有者。
- 自动释放：持有者崩溃后锁最终能过期或被接管。
- 唯一持有者标识：释放时只能删除自己的锁。
- 续租或租约：任务超过 TTL 时要续期，并处理续租失败。
- fencing token：下游使用递增令牌拒绝旧持有者，防止网络分区后的陈旧客户端继续写入。

Redis `SET key value NX PX` 可实现基础租约锁，但释放必须校验 value；单机锁不能自动提供跨节点强一致。数据库唯一键、行锁、ZooKeeper/etcd 等方案应根据故障模型和性能需求选择。

加锁成功后不能假设业务一定能完成；业务操作必须可重试、幂等，并设置最大持有时间。锁超时后原持有者可能仍在执行，因此没有 fencing 的锁不能保护所有外部资源。
