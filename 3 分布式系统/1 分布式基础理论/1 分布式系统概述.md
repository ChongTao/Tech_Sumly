# 1 分布式系统基础

分布式系统由多个通过网络协作的节点组成，对外提供一个整体能力。节点可能并发执行、延迟、丢包、重启或产生网络分区，因此分布式设计的核心不是“把服务拆开”，而是处理不确定性、部分失败和状态协作。

## 1.1 分布式一致性

一致性描述不同节点对数据或操作结果的观察关系。线性一致性要求每次操作看起来像在一个全局时间线上原子执行；顺序一致性只要求符合某个全序但不一定符合真实时间；最终一致性允许短暂差异，但在没有新更新时最终收敛。

一致性、可用性和分区容错不是简单的三选一开关，实际系统应明确读写语义、故障范围、超时行为和业务可接受的数据差异。副本数增加不等于一致性自动增强，复制协议、选主、提交和修复流程同样重要。

## 1.2 网络与时间

网络调用必须假设会延迟、丢失、重复和乱序。超时只能说明调用方没有在期限内得到结果，不代表服务端没有执行成功，因此写操作需要幂等键或状态查询。

不同机器的物理时钟可能漂移，不能用本地时间直接判断全局先后。逻辑时钟、版本号、单调递增序列和因果 ID 可以辅助描述事件顺序；业务展示时间与一致性判断应分开。

## 1.3 Hash 冲突

哈希函数把大量可能的键映射到有限桶，冲突不可避免。链地址法把冲突项放入桶链表或树；开放寻址法在其他位置继续探测。负载因子过高会降低性能，应扩容并重新分布。

分布式哈希还要考虑节点增删造成的迁移。一致性哈希通过环和虚拟节点减少迁移范围，但要额外处理热点、数据副本和节点故障；它不是一致性协议。

## 1.4 设计原则

- 明确数据的权威来源、所有者和修改入口。
- 为每个远程调用定义超时、重试、幂等和降级行为。
- 将可重试的暂态错误与不可重试的业务错误区分开。
- 为消息和任务设置唯一 ID、状态机、过期时间和补偿路径。
- 记录请求、事件、版本和节点信息，保证故障可以重放和审计。
