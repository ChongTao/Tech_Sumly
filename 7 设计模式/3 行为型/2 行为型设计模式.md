# 2 行为型设计模式

行为型模式关注对象之间的职责分配和通信方式。常见模式包括观察者、责任链、命令、状态、模板方法、迭代器、中介者和访问者。

## 2.1 常见模式

| 模式 | 作用 | 风险 |
| :--- | :--- | :--- |
| 观察者 | 发布状态变化并通知订阅者 | 订阅泄漏、通知顺序和失败处理 |
| 责任链 | 将请求沿处理器链传递 | 链过长时难以排查和保证顺序 |
| 命令 | 将请求封装为对象 | 可支持队列、撤销和审计 |
| 状态 | 将状态相关行为封装到状态对象 | 状态过多时需要明确转移图 |
| 模板方法 | 固定流程骨架，允许步骤变化 | 继承层次过深会降低灵活性 |

模式选择应从变化点和业务不变量出发。事件通知适合解耦，但如果调用方必须立即知道结果，使用异步观察者会引入最终一致性和失败重试；此时应明确返回状态和补偿路径。
