# 1 高可用与容灾基础

高可用关注服务在故障下仍能提供可接受的服务；容灾关注故障造成数据或服务不可用时的恢复能力。两者都不能脱离业务目标，应先定义 SLO、RTO（恢复时间目标）和 RPO（可接受的数据丢失量）。

## 1.1 故障域与冗余

故障域是可能同时失效的资源集合，例如进程、主机、机架、可用区和地域。多副本只有分散在独立故障域中才真正提高可用性；把多个实例放在同一主机上不能抵御主机故障。

- 无状态服务优先水平扩展，实例间不保存必须共享的会话状态。
- 有状态组件需要副本、选主、数据复制和明确的脑裂处理。
- 负载均衡应检查真实就绪状态，而不是只检查进程或端口。
- 依赖服务也必须纳入故障域分析，不能只扩容入口服务。

串联系统的整体可用性通常受最弱环节影响；并联副本可提升可用性，但副本之间的复制、切换和一致性机制也会引入新的故障面。

## 1.2 超时、重试与熔断

每次跨进程调用都应设置连接、读写和整体超时，并留出重试预算。重试只适合明确的瞬时错误，且需要指数退避、随机抖动、最大次数和幂等保证。多个层级同时重试会形成重试风暴。

熔断器在连续失败或延迟超过阈值时暂时阻断调用，经过探测窗口后逐步恢复。限流控制进入系统的请求量；舱壁隔离限制不同租户、接口或依赖占用的线程和连接资源。三者应结合使用。

## 1.3 容灾策略

| 策略 | RTO/RPO 特征 | 代价与注意 |
| :--- | :--- | :--- |
| 备份恢复 | RTO 较长，RPO 取决于备份间隔 | 必须定期演练恢复 |
| 冷 standby | 需要启动和加载数据 | 成本较低，切换较慢 |
| 温 standby | 服务和数据保持部分就绪 | 需要同步和切换流程 |
| 热 active-active | 切换快，RTO 较低 | 数据一致性、流量和成本复杂 |

容灾演练应覆盖依赖不可用、网络分区、数据误删、凭据失效和区域故障，并记录发现时间、决策、切换、恢复和回切结果。未经演练的备份和切换脚本不能视为可靠能力。
