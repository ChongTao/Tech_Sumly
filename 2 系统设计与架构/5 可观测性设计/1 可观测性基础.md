# 1 可观测性基础

可观测性通过指标（Metrics）、日志（Logs）和链路追踪（Traces）回答“系统发生了什么、影响多大、为什么发生”。三者应使用统一的服务名、实例名、环境和 trace ID 关联。

## 1.1 指标

服务指标通常包含流量、错误、延迟和饱和度（RED/USE 思路）。应监控请求总量、成功率、P95/P99 延迟、并发、队列积压、CPU、内存、磁盘和连接池。

指标标签要控制基数。不要把用户 ID、请求 ID 或完整 URL 作为高频标签，否则时间序列数量可能失控；这类信息放入日志和追踪更合适。

## 1.2 日志

结构化日志至少包含时间、级别、服务、实例、事件名、错误码和 trace ID。错误日志应包含可行动的上下文，但要对密码、令牌、个人信息和业务敏感字段脱敏。

日志系统需要考虑采集失败、磁盘占满、轮转、保留期、索引成本和访问权限。异常重试应避免每次循环都打印完整堆栈，可采用采样、聚合和限频。

## 1.3 链路追踪

入口生成或接收 trace ID，跨 HTTP、RPC、消息队列和异步任务传播上下文。一个 trace 可以包含多个 span，记录服务、操作、开始时间、持续时间和错误。

异步消息需要同时记录生产 span、消息 ID、消费 span 和父子关系；批量任务要防止一个 trace 包含无限 span。采样应优先保留错误、慢请求和关键业务流量。

## 1.4 告警与排障

告警应围绕用户影响和 SLO 设置，避免只对单一 CPU 阈值告警。每个告警都应有负责人、影响描述、排查链接、升级路径和恢复确认方式。

排障顺序通常是确认影响范围、定位时间窗口、检查依赖和资源、对比变更，再进行止损和根因分析。监控系统自身也需要可用性、数据延迟和采集丢失监控。
